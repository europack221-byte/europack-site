يوروباك — نسخة ربط Supabase + Netlify (نسخة تجريبية تقنية، لا تستقبل طلبات حقيقية قبل الاختبار)

مهم: هذه الحزمة تحتوي Netlify Functions، ولذلك لا تعتمد على رفع ملف HTML أو ZIP إلى منطقة Drag & Drop فقط. استخدم ربط مستودع GitHub مع Netlify (أو Netlify CLI) لتجميع الوظائف.

1) أنشئ مستودع GitHub خاصاً وارفع جميع ملفات هذا المجلد إلى جذر المستودع (index.html وapp.js وlogo.jpg وpackage.json وnetlify.toml ومجلد netlify).
2) Netlify -> Add new project -> Import an existing project -> GitHub -> اختر المستودع.
3) إعدادات البناء: Publish directory = . ؛ لا يلزم أمر build؛ Netlify سيجهز الوظائف عبر esbuild.
4) في Netlify -> Project configuration -> Environment variables أضف:
   SUPABASE_URL = https://yywpdttvqxtvkcfuyumb.supabase.co
   SUPABASE_PUBLISHABLE_KEY = مفتاح sb_publishable الخاص بالمشروع
   SUPABASE_SERVICE_ROLE_KEY = مفتاح service_role السري من Supabase (متغير على الخادم فقط، لا تضعه في HTML أو GitHub أو المحادثة)
   انتبه: service_role مفتاح عالي الامتيازات؛ خزنه في متغيرات البيئة فقط ولا تشاركه.
5) أعد Deploy بعد حفظ المتغيرات.
6) افتح رابط Netlify؛ جرّب حساب الإدارة باستخدام بيانات مستخدم Supabase الذي أنشأته.
7) اختبر طلباً تجريبياً ثم ظهوره في لوحة الإدارة، وجرّب صورة إيصال ومراجعتها وتأكيدها وطباعتها A4.

حدود النسخة الحالية التي يجب إصلاحها قبل إطلاقها للجمهور:
- لا يوجد CAPTCHA أو حماية إساءة استخدام/تحديد معدل طلبات فعالة على endpoint العام. لا تنشر الرابط للزبائن قبل إضافة حماية خادمية.
- إنشاء الزبون والطلب والفاتورة يتم بعدة عمليات؛ إذا تعطل إنشاء الفاتورة يمكن أن يبقى طلب غير مكتمل. يحتاج عملية قاعدة بيانات ذرية (RPC/transaction) للإنتاج.
- إشعارات تلغرام والبريد غير مفعلة؛ الموجود حالياً سجل إشعارات داخل الإدارة ويحتاج تحديثاً يدوياً.
- إيصالات شام كاش تسجل معلقة حتى يؤكدها المدير. إثبات الدفع ليس تأكيداً بنكياً.
- طباعة فلكسو متاحة كخيار لكنها لا تضاف للسعر لعدم تزويدنا بأسعارها؛ تحتاج إكمال قواعد تسعير الكليشات والطباعة والقوالب.
- المعرض وإدارة الصور وباركود شام كاش ليست موصولة بعد في هذه الحزمة، والطلبات القديمة في V9 لا تنتقل تلقائياً.
- لم تُختبر هذه النسخة على خادم Netlify/Supabase الحقيقي؛ تم فحص بناء JavaScript فقط.
- لم يتم تفعيل realtime بعد؛ تحديث لوحة الإدارة يتم بزر «تحديث البيانات».
- سعر الفاتورة يتم حسابه على الخادم من أسعار قاعدة البيانات، لكن تأكد من مطابقة قواعد التسعير المحاسبية قبل التشغيل.

المشروع مستقل عن أي متجر سابق. لا تستخدم قاعدة بيانات مشروع آخر.
